# Architectural decision log

- ADR-001: Flutter mobile-first with Supabase backend. Why: rapid cross-platform MVP with strong auth/data workflows.
- ADR-002: Family Circle as subscription entitlement owner, not individual child/member. Why: one payment unlocks household.
- ADR-003: No child-facing commerce. Why: child safety and trust.
- ADR-004: Rules-based candidate filtering precedes AI recommendation. Why: safety and predictability.
- ADR-005: Global approved recipe library separate from private household overlays. Why: data reuse without leaking preferences.
- ADR-006: Progressive onboarding plus explicit correction. Why: lower friction, avoid intrusive data collection.
- ADR-007: SNAP manual deposit and amount in MVP; authorized balance API only future. Why: credentials and access risk.
- ADR-008: Non-vote is not a dislike. Why: distinguish absence from explicit negative signal.
- ADR-009: Individual screen reference PNG + matching Markdown implementation contract. Why: consistent agent implementation.
- ADR-010: Only adult-authorized production release/billing/third-party spending. Why: autonomous coding is not autonomous business risk acceptance.
